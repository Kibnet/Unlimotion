# SPEC: Исполняемый BDD-мост восстановления JSON (SC-0009-003)

## Контекст

`SC-0009-003` и правило `GR-027` требуют, чтобы загрузка локальных задач не ломалась на JSON с пропущенными запятыми и не принимала migration reports за задачи. Оба аспекта уже покрыты отдельными регрессионными тестами, но не связаны с исполняемым BDD-сценарием.

## Объём

- Добавить тестовый контракт, step definitions и исполняемый сценарный тест для `SC-0009-003`.
- Связать мост с `JsonRepairingReaderTests` и `UnifiedTaskStorageMigrationRegressionTests`, не меняя их реализацию и аннотации.
- Дополнить `storm.json` и шесть текущих STORM-отчётов для `TS-0059` и `SD-0131`--`SD-0134`.

## Вне объёма

- Не менять production code, существующие tests, test annotations, `.feature` и acceptance criteria.
- Не менять Git backup behavior, поскольку он относится к отдельной истории `ST-0010`.

## Критерии приёмки

1. Новый тест исполняет четыре шага `SC-0009-003` и проверяет `SD-0131`--`SD-0134`.
2. Контракт выполняет действующие проверки ремонта JSON и загрузки с migration reports; любой сбой делает BDD-сценарий failing.
3. После `/storm:bdd-sync` и `/storm:bdd-lint` сценарий имеет статус `passing`, связан с `TS-0059`, а `ST-0009` достигает 3/3 step-executable scenarios.
4. Проходят сборка тестового проекта, новый BDD-тест, затронутые наборы регрессии, валидатор STORM и `git diff --check`.

## Риски и откат

Мост только оркестрирует публичные существующие тесты. Изменения ограничены новым тестовым кодом и продуктовой трассируемостью; откат удаляет их без влияния на продукт.
