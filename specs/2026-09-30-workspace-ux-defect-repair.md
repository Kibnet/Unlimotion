# Доведение рабочего пространства и ленты после прогона 13 сценариев

## 0. Метаданные

- Тип: `delivery-task`, .NET desktop/Avalonia + `ui-automation-testing`; контекст `testing-dotnet`, для исключения UI-потока — .NET runtime debug. Применены `creator-vibe-lens`, `model-behavior-baseline`, `tool-execution-baseline`, `quest-governance/mode`, `testing-baseline`, `review-loops`, локальный `AGENTS.override.md`, скиллы `creator-vibe`, `appautomation`, `record-app-screen`.
- Владелец: пользователь и агент; масштаб: **large/expanded**, поскольку затронуты навигация, рабочие представления, потоки UI, настройки и несколько тестовых проектов.
- Модель/поверхность: модель агента не влияет на runtime приложения; работа в локальном Codex на Windows, .NET SDK 10.0.401, AppAutomation 1.8.0 (проверено в `.csproj`). Eval моделей — не применимо.
- Ветка: `feat/daily-feed`, HEAD при подготовке `74ba8292`; много существующих незакоммиченных изменений, в том числе в целевых файлах. Сохранять их и патчить поверх актуального содержимого, без rebase/commit/push по умолчанию.
- Основание: [аудит UX-01–13](2026-09-27-workspace-user-story-ui-audit.md), просмотренный Headless PNG длинного дня и нативный FlaUI repro контекстного меню.

## 1. Цель и исходное поручение

Пользователь: «Во первых убери или обнови неактуальные тесты компоновки. Во вторых исправь выявленные недостатки». Успех означает, что тесты проверяют нынешнюю компоновку, найденные дефекты устранены в обычном приложении, 13 сценариев и смежные проверки дают честный результат, а вкладки/лента/задачи остаются удобными в повседневной работе. Исходный UX-05 должен сразу показывать найденную строку длинного дня; стандартное контекстное меню ссылки должно давать «Открыть рядом».

Результат: локальные изменения кода и тестов, регрессионные UI-тесты, просмотренные PNG и по возможности парные видео, журнал проверок в этой SPEC. Стоп: не называть работу завершённой при красном обязательном тесте или непроверенном исходном сценарии; не удалять тест ради зелёной цифры; не затрагивать реальную базу заметок.

## 2. Проверенное AS-IS

- Последний rendered Headless-прогон 13 историй: 12 PASS / UX-05 FAIL-PRODUCT. Поиск выбирает день из архива за три года, но строка 137 из 200 не попадает во viewport; [PNG](../chat-artifacts/story-coverage-exec/workspace-user-stories/c0bb13b0e78841959fe3e5b631545612/ux05-long-historical-day.png) осмотрен.
- Native FlaUI трижды вызвал меню блока вместо меню ссылки. В `MarkdownBlockLivePreviewEditor.ContextMenu.cs` туннельный `ContextRequested` перехватывает событие, включая источник с собственным `ContextMenu`; `MarkdownBlockPreviewControl` уже создаёт нужные команды New tab/Adjacent pane.
- `FeedViewModel.OpenSearchResultCoreAsync` разрешает якорь и создаёт `WorkspaceLocation` с BlockIndex. `FeedControl.NavigateToFeedBlock` отклоняет навигационное событие, когда текущий pane ещё не активен/не совпал путь; затем пытается `BringIntoView` конкретный preview. Не доказано, какая из этих стадий теряет scroll — это проверить перед фиксом.
- В полном rendered Headless-наборе на момент аудита 65 PASS / 12 FAIL из 77. Помимо UX-05, красные: Feed unified/search/shell/filename, архивный status contract, три копии старого details-toggle, settings recovery cross-thread, remote-type, task-spaces. После удаления обращения к исчезнувшему `TasksModeRoot` один shell-тест дошёл до следующего старого ожидания карточки. Этот отчёт — baseline, а не 12 подтверждённых продуктовых дефектов.
- `TaskRelationsControl.RelationEditor_OnPropertyChanged` вызывает `RefreshEditorState` напрямую; при восстановлении настроек зафиксирован `InvalidOperationException` о чужом UI-потоке. Установить источник события и ограничить обновление UI dispatcher с учётом lifetime контрола.
- `IsUnlocked` исключает Archived, но не Completed; отдельно действуют сохранённые status filters, где Completed по умолчанию скрыт. Снимок с завершённой задачей и отсутствие нового шага в «Доступных» **пока не доказывают баг**: возможны пользовательский фильтр, блокер, статус или критерии. Нужна детерминированная диагностика до изменения правил.
- В двух Feed-панелях один `FeedViewModel` показывает два одинаковых reminder-баннера. Внешний `unlimotion://` из ОС проверен недостаточно; внутренний клик UX-09 не равен hot/cold activation.

## 3. Корневая проблема

После смены компоновки часть тестов продолжает утверждать старую структуру окна, а несколько реальных переходов не привязаны к устойчивому активному host/scroll/menu состоянию. Из-за смешения устаревших ожиданий с продуктовым дефектом зелёный/красный результат набора сейчас плохо сообщает пользователю качество приложения.

## 4. Цели дизайна

- Одна предсказуемая модель вкладок и панелей: источник и связанная задача доступны рядом; ссылки имеют своё стандартное меню, фон блока — меню блока.
- Поиск ведёт к совпадению, а не лишь к файлу; смена вкладки не теряет якорь.
- Состояние UI обновляется только на UI-потоке; закрытие/смена workspace отменяет отложенное действие.
- Старый тест заменяется актуальным наблюдаемым маршрутом, если пользовательский контракт сохранился; удаляется лишь дублирующий/исчезнувший контракт с обоснованием.
- Никакая правка не подменяет желаемую логику доступности задач догадкой; сохранённые фильтры и реальные блокеры остаются авторитетными.

## 5. Non-Goals

Не перестраивать всю систему вкладок, не менять формат Markdown/хранилища, не мигрировать реальные vault, не выдумывать новую политику статусов, не запускать массовое изменение задач пользователя. Не считать OS-протокол исправленным только по внутреннему клику. Не выполнять Git push/PR/коммит без отдельного запроса.

## 6. Решение

### 6.1 Ответственности

| Поверхность | План |
| --- | --- |
| `FeedViewModel` / `FeedControl` / workspace host | Не терять якорь поиска на асинхронной смене активной вкладки; после материализации целевого блока прокрутить внешний scroller до текста совпадения, учитывая virtualization и отмену старого запроса. |
| `MarkdownBlockLivePreviewEditor.ContextMenu` / `MarkdownBlockPreviewControl` | Если источник или ближайший кликабельный предок имеет собственное меню ссылки, позволить ему обработать `ContextRequested`; на фоне блока открывать только блоковое меню. Проверить одиночное и множественное выделение. |
| `TaskRelationsControl` и source notification | Маршалить UI-bound изменения на dispatcher, не писать в отсоединённый/закрытый control; проверить корректность подписки/отписки. |
| `FeedControl` / workspace shell | Один reminder на активное представление ленты, без дубля в соседней заметке; разбор остаётся вызываемым глобально. |
| `MainWindowViewModel` / task filters | Сначала characterization default/persisted filters и `IsCanBeCompleted` нового child. Исправить только подтверждённое расхождение: Completed по умолчанию скрыт, явный включённый фильтр работает; новый реально доступный шаг виден, а блокированный не подменяет правило и сообщает причину. |
| `UiTests.Authoring`, Headless, FlaUI, component tests | Заменить старые layout assertions на текущие rail/tab/pane операции; оставить status/settings/space функциональные контракты и исправлять их по фактическому repro. Не удалять красный валидный сценарий. |
| Protocol tests | Раздельно проверить internal URI, OS hot/cold activation, отсутствие ID и иное пространство на поддерживаемых платформах/доступной среде. |

### 6.2 Визуальный ориентир и evidence

Минимальный wireframe для двух панелей, без нового постоянного chrome:

```text
верхняя общая строка: [+] [пространство] [назад/вперёд] [поиск] [разбор] [настройки]
панель A: Лента / найденный день                 панель B: Задача или заметка
          ↳ найденная строка видна сразу                    свой scroll
          ↳ один контекстный menu у ссылки
reminder разбора: один раз в активной Ленте; не повторяется в панелях заметок
```

Сравнить до/после в одинаковом окне 1280×800 и узком ~520 DIP: длинный день, меню ссылки, две панели, баннер, возвращение к тому же месту. Базовый PNG уже сохранён. Перед EXEC проверить доступность записи безопасного window-only MP4 (ffmpeg/ffprobe найдены, script доступен); снять `before` нативным автоматизированным flow до product patch и `after` тем же flow. Если интерактивная запись окна невозможна, в журнале назвать объективный отказ и дать rendered Headless PNG + FlaUI лог. Личные уведомления/база не попадают в видео.

## 7–10. Интеграция, совместимость и rollout

События `SearchNavigationRequested`, workspace activation, `ContextRequested`, `PropertyChanged`, status/filter change должны пересчитывать только своё представление. Якорь и scroll остаются состоянием вкладки; общий `FeedViewModel` не должен размножать reminder. Протокол платформы не перерегистрировать без доказанной причины. Сначала failing check и baseline, затем точечный fix, потом cross-pane/shell regression; старые test fixtures не направлять на реальную базу. Никакой миграции файлов.

## 19. Post-SPEC review

- Scope/Evidence: прочитаны предшествующий аудит, его test matrix, исходный UX-05 PNG, relevant current production/test code, central QUEST/testing/UI owners, AppAutomation/recording skills, `git status`/branch/SDK и ссылки на AppAutomation 1.8.0. Реальный прогон в этой SPEC-фазе не выполнялся; baseline — проверенный предыдущий EXEC.
- Contract: исходные два поручения представлены AC1–AC8; не смешиваются stale tests и подтверждённые product bugs. Полный пользовательский сценарий и обычная сборка входят в обязательную проверку.
- Adversarial: возможный false positive Completed/new child из сохранённых фильтров; потеря search event при создании pane; context menu priority; cross-thread callback после detach; OS activation зависит от платформы. Для каждого есть негативная ветвь или точная граница.
- Role-based: UX — видимое совпадение и одно меню/баннер; tester — RED→fix→full suite, не удалять валидный тест; architect — dispatcher/lifetime, no data migration; operations — dirty diff, native video и platform boundary. Business — сохранение пользовательских фильтров/блокеров.
- Findings: `MEDIUM / evidence`: OS hot/cold и видео могут быть недоступны в текущем runtime; действие — попытка на тестовой конфигурации, затем точный fallback без ложного PASS. `MEDIUM / scope`: 12 failures не равны 12 product bugs; действие — поштучная классификация перед исправлением. BLOCKER/HIGH на фазе SPEC не найдено.
- Fix/re-review: не заявлять автоматическое изменение статусов child, сохранить persisted filters, добавить проверку именно viewport и real pointer; перечитаны соответствующие AC/риски.
- Stop decision: **PASS для запроса approval, не для EXEC**. Independent reviewer не запускался: текущий runtime запрещает subagents; это self-review с adversarial fallback.
