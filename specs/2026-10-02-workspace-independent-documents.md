## 1. Overview / Цель

Пользователь должен собирать рабочий экран из независимых документов: например, «Выполняется» слева, «Разблокированные» справа, отдельные карточки задач и заметки в верхнеуровневых вкладках. От того, откуда открыт объект, не должны зависеть его компоновка и команды открытия.

Outcome contract:

- Исходные симптомы: режимы задач вложены в «Задачи»; карточка продолжает жить внутри старого составного экрана; команды открытия не дают очевидного результата; в левой навигации нельзя выбрать место открытия.
- Success means: каждое представление и карточка — самостоятельный документ; нет внутренней полосы режимов; состояние представлений изолировано; история принадлежит вкладке; одинаковые команды работают во всех точках входа.
- Итог EXEC: код, обновлённые UI-тесты исходных 13 пользовательских историй, новые регрессии, просмотренные before/after screenshots и native evidence.
- Stop rules: на SPEC меняется только этот файл. На EXEC нельзя считать задачу завершённой по наличию маршрутов/кнопок или green старых тестов без проверки открытого экрана. Ошибка сохранения/потеря независимости/дублирование объекта блокируют переход и завершение.

## 3. Проблема

Workspace стал оболочкой старого монолитного экрана, а не системой самостоятельных документов. Маршрутизация, визуальный состав и владение состоянием описывают разные модели; отсюда вложенные вкладки, общая история и непоследовательные способы открытия.

## 4. Цели дизайна

- Один уровень вкладок документов, один понятный выбор места открытия.
- История — у вкладки; фильтры, поиск, сортировка, дерево, выделение и scroll — у конкретного представления в текущем пространстве.
- Карточки разделяют доменные данные задачи, но не глобально выбранную задачу/состояние редактора.
- Реиспользовать существующие поля карточки, отношения, фильтры и команды; не копировать бизнес-логику.
- Негативные UI-проверки запрещают лишние панели/внутренние вкладки, а не только находят нужный title.

## 5. Non-Goals

- Не менять статусы, расчёт разблокировки, формат задач/Markdown, редактор блоков или алгоритм разбора.
- Не заменять docking engine, не добавлять произвольное число split-панелей, floating windows или новый layout designer. Сохраняется текущая модель основной и соседней панели.
- Не добавлять экземпляры одного объекта, пользовательские сохранённые представления, новые виды фильтров или синхронизацию истории между устройствами.
- Не обещать новое сохранение вкладок/истории после перезапуска; текущие долговременные настройки, pins и данные сохраняются как прежде.
- Не переписывать HTML-макет в фазе SPEC. Эта SPEC и wireframe — нормативная поправка к нему.
- Не изменять CLI/task-manager, не выполнять commit/push/PR/release без отдельного поручения.

## 6. Предлагаемое решение (TO-BE)

### 6.1 Распределение ответственности

| Компонент | Ответственность |
| --- | --- |
| Shell / MainScreen | Общие пространство, поиск, `+`, настройки; rail; активная панель. Не хранит историю всех документов как пользовательскую навигацию |
| WorkspaceLocation + фабрики | Стабильный тип/ключ представления, локализованный title, scoped identity объекта, locator отдельно от identity |
| WorkspaceNavigation / pane / tab | Открытие, uniqueness, commit guards, история каждой вкладки, перенос/объединение панелей |
| TaskListDocumentViewModel/View, новое имя уточнить в EXEC | Только выбранный список, его фильтры/поиск/дерево/выделение/scroll; не содержит карточку и полосу режимов |
| TaskCardViewModel/View, новое имя уточнить в EXEC | Только выбранная задача, её поля/отношения/источник/следующий шаг; без списка задач |
| Общий task store / сервисы | Единые данные и бизнес-команды. Статус обновляет все затронутые представления без переноса их UI-состояния |
| Document view-state / history entry | Снимки состояния для возвращения, привязанные к объекту/пространству, а не визуальным control или последнему глобальному выбору |
| Общий Open command / menu builder | Здесь / новая вкладка / соседняя панель; различает focus объекта, явный locator и traversal history; используется всеми точками входа |

Граница обязательна, конкретные имена файлов — инженерный выбор. `MainControl` целиком нельзя использовать как содержимое Task/TaskList workspace-маршрута. Переиспользуются выделенные компоненты, а не второй экземпляр монолита с очередными IsVisible-флагами. Legacy control может остаться только для подтверждённых иных host/тестов, но не как пользовательский экран workspace.

### 6.2 Детальный дизайн

**R1. Самостоятельные представления.** Существующие девять режимов становятся отдельными документами: «Все задачи», «Последние созданные», «Последние изменённые», «Разблокированные», «Выполняется», «Выполненные», «Архив», «Последние открытые», «Дорожная карта». Названия брать из актуальных ресурсов приложения. Идентичность — стабильный вид представления, не UI-индекс и не выбранные фильтры. «Задачи» в rail — группа/вход в «Все задачи», не универсальная вкладка-контейнер. Все режимы достижимы через rail/его раскрытие или доступное overflow; существующие режимы не исчезают. В документе нет `MainTabs` или второго переключателя режима; другой режим открывается через общую навигацию.

**R2. Карточка.** Любой маршрут Task монтирует только карточку указанного ID. Обычный клик по названию заменяет документ активной вкладки; Back возвращает к списку. NewTab сохраняет список и создаёт вкладку с названием задачи в той же панели. AdjacentPane сохраняет исходную панель и открывает карточку в текущей вкладке другой панели, создавая панель при необходимости. Создание следующего шага, открытие результата quick capture, переходы по связям и unlimotion://task/... используют тот же контракт. Само сохранение quick capture не навигирует автоматически и сохраняет рабочий контекст UX01. Изменение global CurrentTaskItem не должно заменить другую открытую карточку.

**R3. Состояние и история.** В каждой вкладке собственные entries/index и Back/Forward/history menu. Видимые Back/Forward у каждой группы вкладок; Ctrl+[ / Ctrl+] действуют на активную вкладку. Переключение вкладки, создание соседней и обычный focus не записываются как переходы другого документа. Новый маршрут в той же вкладке обрезает её forward-ветку; фильтрация, scroll, изменение статуса не создают history entry. Запись истории хранит locator и snapshot view-state; переключение сохраняет состояние, возвращение восстанавливает его. Inactive history entries не держат смонтированные UI-контролы. Shared history, если временно нужна внутреннему коду, не управляет пользовательскими Back/Forward и не отображается вместо истории вкладки.

**R4. Независимость представлений.** Общее task-space/storage не означает общих search/filter/selection полей UI. Два разных представления могут быть видимы одновременно; изменение поиска, сроков, длительности, статусов фильтра, сортировки, раскрытия дерева, выделения и scroll в одном не меняет другое. Snapshot включает применимые настройки конкретного режима, а не только срок/длительность. Смена режима не очищает сохранённое состояние другого документа. Статус/текст самой задачи общие и обновляются сразу во всех затронутых документах; это не нарушение изоляции.

**R5. Открытие и понятные названия.** Для ещё не открытого объекта стандартное контекстное меню содержит «Открыть в текущей вкладке», «Открыть в новой вкладке», «Открыть в соседней панели»; для уже открытого применяется ясный reuse-вариант R6. Это три способа открытия одного объекта, не команды перемещения текущей вкладки. Команды «Переместить вкладку в другую панель»/«Объединить панели» остаются отдельными действиями вкладок. Меню доступно по right click, клавиатурному ContextMenu/Shift+F10 и явной кнопке действий для touch. Обычный клик = CurrentTab, Ctrl+клик = NewTab. На narrow AdjacentPane открывает/активирует соседнюю группу, а не невидимый документ.

Обязательные точки входа: все предметные пункты rail (включая pins), строка/название задачи в списке, связи и дочерние задачи карточки, результаты поиска, внутренние ссылки в ленте/заметке. Для группы «Задачи» целевой объект — «Все задачи». «Заметки» остаётся каталогом: способы открытия доступны на конкретных найденных файлах, меню открытия не притворяется открытием абстрактного файла. Для «Разбор» применяются его существующие guards и открытие источника рядом; нельзя потерять эту работу ради универсального меню.

Контекстное меню строки работает с объектом под указателем, а не последней глобально выбранной задачей. Checkbox/status button изменяет только статус; expander — раскрытие; drag/multiselect/операции над выделением не превращаются в переход по названию. Нативное текстовое меню не открывается вторым поверх предметного меню ссылки, но сохраняется там, где пользователь редактирует обычный текст.

**R6. Уникальность и намерение перехода.** В пределах текущего пространства объект имеет максимум один активный экземпляр среди всех вкладок и обеих панелей. Уникальные объекты: каждый вид списка отдельно, конкретная задача по ID, конкретная заметка по нормализованному пути и базе, лента, разбор. Locator/filter/scroll не создают второй объект. Исторические ссылки на объект не считаются экземплярами. Dispatcher различает три намерения; наличие автоматически сохранённого ScrollOffset само по себе не означает explicit locator:

- **FocusObject:** повторное открытие объекта без заданного места любым disposition активирует уже открытую вкладку на её месте; не переносит её, не добавляет вкладку/историю, не сбрасывает фильтры, scroll или редактор.
- **TargetLocator:** результат поиска, «К исходной записи», показ источника разбора или ссылка с явным heading/block/day locator находят ту же owning вкладку, проходят guards исходного и целевого редактора, сохраняют её snapshot и переходят к точному месту. Лента остаётся единственным Feed, даже если меняется день. Изменение locator добавляет запись только в историю owning вкладки; такой же locator повторно фокусируется/подсвечивается без дублирования entry. История исходной вкладки, если она отличается от owning, и все нецелевые документы не меняются. Если ограничивающий фильтр скрывает цель, только в target-документе временно снять мешающее условие с видимым пояснением; сохранить исходный фильтр в предыдущем snapshot, чтобы Back восстановил его. Остальные фильтры/поля/редактор не сбрасываются. Отсутствующая цель даёт понятную ошибку, не focus сегодняшнего дня или случайного блока.
- **TraverseHistory:** восстанавливает snapshot выбранной записи в своей вкладке; для duplicate target действует описанное ниже исключение, а не TargetLocator со старым snapshot чужого документа.

Меню для уже открытого объекта явно показывает «Уже открыт: <панель/вкладка>»; вместо обещания нового экземпляра предлагает «Показать открытую вкладку». У ссылки с locator команда называется «Показать указанное место в открытой вкладке» и сохраняет TargetLocator intent. Requested placement не разрешает duplicate или скрытый move.

При Back/Forward/history menu цель сначала проходит ту же проверку уникальности. Если предыдущий объект сейчас открыт в другой вкладке, показывается этот экземпляр; исходная вкладка и её cursor остаются на месте, история целевой не меняется, её сохранённые фильтры не перетираются старым snapshot. Короткое сообщение объясняет «Документ уже открыт — показана его вкладка». Это явное исключение к обычному возврату внутри вкладки; нельзя молча пропустить запись, прыгнуть на произвольный более старый объект или смонтировать дубль. На границе своей истории Back/Forward disabled независимо от истории соседей.

**R7. Guards, ошибки, lifecycle.** Перед уходом из активного редактора действует существующий async commit gate; focus существующего документа и перенос/закрытие не обходят его. При конфликте/ошибке сохранения текст, маршрут, history cursor и активная панель остаются прежними, ошибка видима и позволяет повторить. Удалённая/недоступная цель не открывает чужой объект: показать ошибку в контексте запрошенной записи с доступным возвратом, не переиспользовать случайную CurrentTaskItem. Повторные async-запросы сериализуются/защищаются от stale completion; после смены пространства старый callback не активирует маршрут. Смена пространства проходит guards всех открытых редактируемых документов до сброса scope/cache; failed commit оставляет прежнее пространство, документы и текст. Dispose снимает подписки старых document views; Back не множит live-коллекции и обработчики. Открытие карточки/истории не запускает полный обход Markdown-базы; inactive документы не рендерятся все сразу.

Закрытие последней вкладки: пустая secondary исчезает; если опустела primary, оставшаяся secondary-группа целиком становится основной с прежними вкладками/историями. Если больше документов нет, создать единственную вкладку «Все задачи». Это сворачивание пустой группы, не повторное открытие/перемещение одного fallback-объекта из непустой группы. Закрытие inactive вкладки не переключает чужую активную вкладку; guard ошибки не удаляет вкладку.

Guards завершаются до изменения pane/tab ownership, history cursor и выбранного scope. Это атомарность UI-перехода, не новая транзакция нескольких файлов: успешные сохранения отдельных редакторов не откатываются при последующем отказе другого guard; весь введённый текст остаётся доступен в прежнем пространстве. Snapshot/navigation mutations применяются только после полного успешного набора guards.

## 7. Бизнес-правила / Инварианты

1. Документ — содержимое одной workspace-вкладки; панель — группа вкладок; отдельный документ не обязательно постоянно занимает отдельный split.
2. У каждого списка свой stable key. Фильтр не часть identity; другой список — другая identity. Task и TaskList не взаимозаменяемы.
3. У каждой вкладки одна независимая история; одинаковый объект в истории нескольких вкладок не означает несколько live экземпляров.
4. Domain state общее; view-state изолировано. Обновление Task A не должно заменить редактор Task B.
5. Reuse существующего объекта имеет приоритет над requested placement. Перемещение — явная отдельная команда, не side effect открытия. Уникальность не отменяет explicit locator: место меняется только в owning документе по R6, не посредством дубля.
6. Caption берётся из объекта/вида; смена названия задачи обновляет caption, но не identity/history structure.
7. Новая навигация добавляется только после успешного guard. Ошибки не обрезают forward history и не активируют случайную строку.
8. «Горящие» — последний день + просроченные, как уже определено пользователем; новый workspace не меняет этот фильтр или порядок выбора работы.

## 8. Точки интеграции и триггеры

- `MainScreen` rail / global search / pins / shortcuts → единый Open command с конкретным target и disposition.
- Название задачи, links/relations/children, Feed Markdown links, protocol handler, next-step creation → тот же dispatcher. Открытие не зависит от события изменения global selection.
- TaskList commands → собственный selection/filter context; Card commands → ID текущего документа, не global CurrentTaskItem.
- Pane activation/tab activation → bindings активной истории и горячих клавиш; не запись глобального перехода.
- CommitBeforeLeaving → snapshot только после успешного commit; также защита замещаемой соседней вкладки.
- Task store updates → все затронутые документные projections, без синхронизации их UI-фильтров.
- Scope change / close / dispose → отмена stale requests, освобождение подписок, очистка scoped state, сохранение прежних guards.

## 9. Изменения модели данных / состояния

Stable TaskListKind/аналог, явные фабрики location, scoped ObjectKey, reusable document state. Per-tab history хранит locator и полный применимый snapshot; flags активного документа не являются source of truth других списков. Поля domain task/file не добавляются. Персистентные настройки существующих фильтров не удаляются: при первом открытии они могут задавать default, но текущая изоляция UI не строится на чтении единственного глобального поля.

Политика snapshot: уход сохраняет состояние текущей записи; Back/Forward восстанавливает snapshot при реально выполняемом переходе; FocusObject сохраняет текущее состояние. TargetLocator сохраняет предыдущий target snapshot и добавляет новое место только в owning history; TraverseHistory не выдаёт старый snapshot за explicit request к уже занятой чужой вкладке. История не владеет UI/control; открытый объект имеет одного live owner. Retained state ограничивается workspace session и освобождается при reset/dispose; не хранить copies task store/Markdown для каждой записи истории.

## 10. Миграция / Rollout / Rollback

- `tasktab:0..8` интерпретировать как stable виды на границе старых маршрутов; не менять содержимое файлов задач.
- Старые bindings/commands на shared history заменить во всех пользовательских входах. Не поддерживать одновременно две конкурирующие модели Back.
- Если runtime state старого контейнера не переносится, при первом открытии взять текущие настройки нужного режима; не обещать несуществующее restart restore.
- Сохранить достижимость всех режимов и действия списка/карточки, текущие pins/settings/provenance и Feed guards.
- Rollback — отдельный revert implementation commits по разрешению пользователя; domain/config schema не меняется. Проверка отката: обычный launch и контрольные fixture-файлы читаются, задачи/заметки не потеряны. Не откатывать unrelated пользовательские изменения.

## 11. Тестирование и критерии приёмки

### Acceptance Criteria

1. **AC1:** каждый из девяти режимов открывается самостоятельной именованной вкладкой; UI списка не содержит вложенных вкладок режимов или карточки; два разных вида видимы одновременно.
2. **AC2:** Task из списка/ленты/поиска/связи/следующего шага содержит только карточку нужного ID, без списка/внутренних режимов. Две разные открытые карточки не подменяют друг друга.
3. **AC3:** Back/Forward/menu/Ctrl shortcuts относятся к активной вкладке; new navigation обрезает только её forward branch; inactive tabs history/index не меняются.
4. **AC4:** все применимые filters/search/sort/tree expansion/selection/scroll двух представлений независимы; возвращение восстанавливает состояние, без сброса из-за активации другой панели.
5. **AC5:** изменения статуса/описания/сроков/длительности обновляют общие task data и затронутые projections, не меняя независимые фильтры/открытые задачи.
6. **AC6:** три ясные команды/Already-open вариант доступны из rail, строк/связей, поиска, Feed/note links; target right click — объект под указателем; touch/keyboard путь работоспособен. Нет дублирующего предметного/нативного меню ссылки.
7. **AC7:** CurrentTab/NewTab/Adjacent дают строго результаты R2/R5; Ctrl работает из тех же предметных входов; narrow активирует реальную целевую группу.
8. **AC8:** повторное FocusObject открытие любого объекта всеми dispositions сохраняет tab ID/count, view-state и histories; TargetLocator переиспользует тот же tab ID без duplicate, переводит к нужному месту только owning документ/его history и защищает draft guards; каждый вид списка уникален отдельно; move/merge не создают дубли.
9. **AC9:** история восстанавливает filtered list после карточки, не меняя соседний документ; duplicate history target обрабатывается ровно по R6 с пояснением, без случайного jump/overwrite. Поиск/исходник/anchor в уже открытом Feed/Note дают точный видимый блок, Back возвращает прежний target locator/filter; нецелевые history/filter не меняются, независимо от того, в какой панели owning документ. Нет цели — понятный error с return path.
10. **AC10:** сохранение/конфликт/pending navigation защищают исходный и замещаемый редактор; failed commit сохраняет текст, cursor, route/pane. Next-step/relations/actions направлены на правильный task ID.
11. **AC11:** move/merge/close сохраняют identity/history/state оставшихся вкладок; закрытие последней primary-вкладки сохраняет целиком оставшуюся группу; совсем пустой workspace получает единственный All Tasks; нет duplicate/случайного переноса fallback; старые subscriptions освобождаются.
12. **AC12:** scope change не смешивает задачи/заметки одинаковых ID/path; при failed guard активного, соседнего или inactive editor прежний scope/tabs/history/drafts не меняются; успешный переход делает один reset, stale callbacks не активируют старые маршруты; прежние scoped настройки и pins работают.
13. **AC13:** на 1280×800, 640×800 и 390×800 просмотрены нужные открытые состояния: два списка/карточка/меню/история; controls не перекрываются, history group-local, режимы доступны, карточка/список скроллятся независимо. Адаптация к темам не ломает читаемость.
14. **AC14:** исходные UX01—UX13 обновлены на новый UI, реально исполняются без Skip и проходят; обязательные suites/build проходят; новые проверки запрещают legacy composition. Не достаточно assert title или прямого выставления VM-поля вместо операции, которую проверяем.

## 12. Риски и edge cases

- Глобальные mode/selection bindings и команды могут незаметно обслуживать не тот документ. Требуются matrix tests для двух разных task cards и views, включая родителя/следующий шаг/clipboard/drag/multiselect.
- Извлечение карточки не должно потерять поля, связи, criteria, recurrent/settings/status affordances и существующие команды. Characterization актуальных controls + полная регрессия.
- Unique-object правило конфликтует с некоторыми cross-tab historical targets: R6 намеренно раскрывает reuse, без дублирования и без переписывания истории другого документа.
- Независимые projections могут увеличить subscriptions: общий store, dispose и отсутствие смонтированных history controls; не копировать полный dataset в entry.
- Перенос control нельзя считать переносом ViewModel state. Snapshot и tab identity проверять после настоящего move/merge.
- Native/FlaUI требует активной Windows-сессии; её недоступность — validation blocker с честным incomplete, не замена mandatory run статическим анализом.
