[English](README.md)

Unlimotion — планировщик, в котором задачи образуют граф: одну задачу можно включить в несколько проектов, разбить на шаги и связать с задачами, от которых зависит её выполнение.

## Основные возможности

- Вложенность без ограничения числа уровней и несколько родителей у одной задачи.
- Зависимости и список разблокированных задач, помогающий выбрать следующий шаг.
- Отдельные пространства для работы, личных дел и других областей.
- Критерии выполнения, плановые даты и повторение целого дерева задач.
- Локальные JSON-файлы и настраиваемое резервное копирование через Git.
- CLI для автоматизации и работы агентов с теми же правилами задач.

Она может отличаться от последнего стабильного релиза: например, текущая иконка и восстановление настроек добавлены после 1.31.1. Версия, показанная в тестовой сборке, не является номером опубликованного релиза.

## Скачать и установить

Готовые самодостаточные опубликованные сборки доступны на странице [последнего релиза GitHub](https://github.com/Kibnet/Unlimotion/releases/latest). Для них не требуется .NET SDK. Наличие опубликованного файла не гарантирует совместимость с каждой версией ОС: полная матрица smoke-тестов платформ ещё формируется.

| Доступная сборка | Какой файл выбрать | Текущий статус проверки |
| --- | --- | --- |
| Windows x64 | `Unlimotion-win-Setup.exe` или `Unlimotion-win-Portable.zip` | Опубликовано. Проект пока не публикует проверяемое подтверждение Authenticode-подписи. Microsoft Defender SmartScreen может показать предупреждение. |
| Linux x64 (AppImage) | `Unlimotion.AppImage` | Опубликованный универсальный вариант для Linux; совместимость с дистрибутивами ещё не проверена полной smoke-матрицей. |
| Linux x64 (.deb) | `Unlimotion-v<version>.deb` | Предварительная сборка. Совместимость с актуальными выпусками Debian пока не подтверждена. |
| macOS x64 | `Unlimotion-osx-Setup.pkg` или `Unlimotion-osx-Portable.zip` | Сборка для Intel. Проект пока не публикует проверяемое подтверждение Developer ID-подписи и notarization. |
| macOS arm64 | `Unlimotion-osx-arm64-Setup.pkg` или `Unlimotion-osx-arm64-Portable.zip` | Сборка для Apple Silicon. Проект пока не публикует проверяемое подтверждение Developer ID-подписи и notarization. |
| Android arm64 | `Unlimotion-v<version>-android-arm64.apk` | APK для установки вручную. Проект декларирует минимум Android 6.0 / API 23, но это не гарантия совместимости со всеми устройствами. |
| Android x64 | `Unlimotion-v<version>-android-x64.apk` | APK для установки вручную, прежде всего для устройств и эмуляторов x86_64; действует та же оговорка о минимальной версии Android. |

- Portable ZIP для Windows или macOS нужно распаковать перед запуском находящегося внутри приложения.
- После загрузки AppImage выполните:

```bash
chmod +x Unlimotion.AppImage
./Unlimotion.AppImage
```

- В macOS проект пока не публикует проверяемое подтверждение подписи и notarization для этих пакетов. Gatekeeper может заблокировать их. Если вы доверяете загруженному файлу, следуйте официальной инструкции Apple [Open Anyway](https://support.apple.com/en-us/102445). Изменение прав файлов не подтверждает доверие или notarization.
- Android устанавливается вне магазина приложений. ОС может запросить разрешение на установку из выбранного источника; точный сценарий зависит от версии Android и устройства. При обновлении из приложения Android скачивает подходящий APK и запрашивает системное подтверждение установки.
- Встроенное обновление desktop-приложения доступно, только когда Velopack распознаёт текущую установку как управляемую. Portable-сборки и запуск из исходников не должны полагаться на этот механизм — для них используйте страницу Releases.

## Быстрый старт

1. Откройте приложение и создайте задачу кнопкой **➕**. Дайте ей название, например «Подготовить поездку».
2. В карточке справа добавьте описание и критерии выполнения — что должно быть сделано, чтобы считать задачу завершённой.
3. Создайте вложенные шаги через **Ctrl+Tab**, например «Выбрать даты» и «Купить билеты». Если один шаг зависит от другого, добавьте блокирующую связь.
4. Откройте вкладку **Разблокированные** и выберите подходящие фильтры статуса и времени. Здесь можно найти задачи, которым уже не мешают незавершённые подзадачи и блокеры.
5. Подготовленную задачу переведите в **Выполняется**, а после выполнения критериев — в **Выполнено**. Если переход недоступен, переключатель статуса покажет причину.

**F1** открывает справочник горячих клавиш. Для разделения рабочих и личных задач создайте отдельные пространства в настройках.

## Как устроены задачи

### Пространства задач

Один экземпляр приложения может хранить несколько именованных пространств задач. Переключайте активное пространство селектором в шапке, а в первом разделе настроек добавляйте, переименовывайте, переключайте и удаляйте пространства из списка.

Одновременно активно только одно пространство. Его источник задач и полный профиль синхронизации Git изолированы от остальных: задачи разных пространств не показываются вместе, а связи между ними запрещены. Чтобы настроить хранилище или Git другого пространства, сначала переключитесь на него. Удаление пространства удаляет только его конфигурацию и сохранённые учётные данные из приложения — файлы задач и удалённый репозиторий не удаляются и не перемещаются.

### Состояния задачи

Любая задача может находиться только в одном из пяти статусов.

1. Не готово - пустой квадрат
2. Подготовлено - квадрат со знаком `!`
3. Выполняется - квадрат со знаком `play`
4. Выполнено - квадрат с галочкой
5. Архивировано - квадрат с квадратом внутри

**Подготовлено** означает, что контекста достаточно, чтобы взять задачу в работу или делегировать её. Начать задачу можно, когда завершены её активные подзадачи и блокеры и наступила плановая дата начала. Для завершения также нужно выполнить все критерии. Будущая дата начала сама по себе не блокирует завершение.

При архивировании приложение может предложить архивировать активные вложенные задачи — так можно убрать из работы весь процесс, сохранив его историю.

<details>
<summary>Подробные правила статусов и формата обмена</summary>

Статус жизненного цикла, доступность по графу и ограничения переходов — разные понятия:

- `Подготовлено` означает, что в задаче достаточно контекста, чтобы её можно было брать в работу или делегировать.
- Доступность по графу вычисляется по активным невыполненным вложенным задачам, прямым блокерам и блокерам, унаследованным от родительских задач. Контрол статуса недоступной по графу задачи отображается с прозрачностью `0.4`; выполненные и архивные блокеры её не блокируют.
- Будущая плановая дата начала ограничивает только переход в `Выполняется`. Она не меняет доступность по графу, выборку «Разблокированные» и прозрачность.

Каноническая матрица переходов:

| Текущий \ запрошенный | Не готово | Подготовлено | Выполняется | Выполнено | Архивировано |
| --- | --- | --- | --- | --- | --- |
| Не готово | Без изменений | Разрешено | Ограничения старта | Ограничения завершения | Разрешено |
| Подготовлено | Разрешено | Без изменений | Ограничения старта | Ограничения завершения | Разрешено |
| Выполняется | Разрешено | Разрешено | Без изменений | Ограничения завершения | Разрешено |
| Выполнено | Разрешено | Разрешено | Запрещено | Без изменений | Запрещено |
| Архивировано | Разрешено | Разрешено | Запрещено | Запрещено | Без изменений |

`Ограничения старта` требуют доступности по графу и наступившей плановой даты начала. `Ограничения завершения` требуют доступности по графу и выполнения всех критериев завершения. Запрос текущего статуса ничего не меняет и не добавляет запись в историю.

Если задача в статусе `Выполняется` теряет доступность по графу или получает будущую плановую дату начала, система один раз переводит её в `Подготовлено` и добавляет системную запись в историю. При разархивации `Не готово` восстанавливается как `Не готово`, а `Подготовлено` и `Выполняется` — как `Подготовлено`. Невалидные записи истории игнорируются, поэтому более старая валидная неархивная запись всё ещё может определить результат; предыдущий статус `Выполнено` или отсутствие любой валидной неархивной записи дают безопасный резервный вариант `Не готово`.

При импорте/экспорте Markdown outline используются маркеры:

| Маркер | Статус |
| --- | --- |
| `[ ]` | Не готово |
| `[!]` | Подготовлено |
| `[>]` | Выполняется |
| `[x]` | Выполнено |
| `[#]` | Архивировано |

Один и тот же переключатель статуса доступен в списках задач, дорожной карте и карточке текущей задачи. Он скрывает текущий статус и показывает остальные четыре цели; запрещённые цели остаются видимыми, но недоступны и содержат локализованную причину. Telegram-бот показывает только разрешённые переходы в другие статусы и применяет те же правила хранилища.

### Связи задач

У задачи есть четыре вида связей:

1. **Родительские задачи (Parents)** — задачи, частью которых она является.
2. **Вложенные задачи (Containing)** — её собственные шаги и составные части.
3. **Блокирующие задачи (Blocking)** — задачи, от которых зависит её доступность.
4. **Заблокированные задачи (Blocked)** — задачи, доступность которых зависит от неё.

### Иерархия задач

Все задачи имеют своё место в общей древовидной иерархии. Самый первый уровень называется корневым, на нём находятся задачи, у которых нет связей с родительскими задачами.
Любая задача может стать дочерней для другой задачи, визуально это выглядит как вложенность в дереве задач.
В отличие от других планировщиков задач, в Unlimotion позволяется одной задаче быть дочерней сразу для нескольких других задач.
Это бывает удобно в случаях, когда задача имеет межпроектное значение и не может быть отнесена только к одной родительской задаче.
Также эту особенность можно использовать как замену тэгам, можно создать родительскую задачу с определённым смыслом и добавить в неё имеющиеся задачи как дочерние, которые имеют отношение к этому смыслу.
Это позволит наблюдать одну и ту же задачу в разных срезах на уровне иерархии.

### Блокировка

Недоступную по графу задачу нельзя начать или завершить, пока она не станет доступной. Её контрол статуса отображается с прозрачностью `0.4`.

Задача недоступна по графу, если у неё есть:

1. Активные невыполненные вложенные задачи (Containing).
2. Активные невыполненные прямые блокеры (Blocking).
3. Активные невыполненные блокеры у любой родительской задачи (Parents).

Архивные и выполненные связанные задачи не считаются невыполненными блокерами. Доступность по графу не мешает перевести задачу в `Не готово`, `Подготовлено` или `Архивировано`, если целевой статус разрешён матрицей жизненного цикла.

### Планирование и повторение

В карточке задачи можно задать плановые начало, длительность и окончание, отметить её как важную и добавить проверяемые критерии выполнения.

Чтобы настроить повторение, сначала выберите дату начала, затем шаблон: например, ежедневно, по рабочим дням или выбранным дням недели. Очистка даты начала сбрасывает повторение.

Следующее повторение получает **собственное поддерево**: новые задачи, критерии и внутренние связи, включая несколько уровней вложенности. Даты сдвигаются для нового повторения; внешние связи исходного поддерева не копируются. Это подходит, например, для регулярного обзора проекта с одинаковым набором шагов.

## Горячие клавиши и работа с задачами

### Создание задач

Создание новых задач всегда происходит относительно выбранной задачи. Чтобы это сделать можно воспользоваться кнопками на правой панели сверху со знаком "➕" или использовать горячие клавиши:

- **➕Sibling (Ctrl+Enter)** - Создать задачу на том же уровне, что и выбранная
- **➕🔒Sibling (Shift+Enter)** - Создать задачу на том же уровне, что и выбранная и заблокировать её выбранной
- **➕Inner (Ctrl+Tab)** - Создать вложенную задачу внутри выбранной
- **Завершить текущую задачу (Ctrl+D)** - Перевести выбранную/текущую задачу в завершённые

Кнопка **Показать горячие клавиши** в настройках и клавиша **F1** открывают полный встроенный справочник сочетаний.

После создания задачи нужно заполнить название текущей задачи, потому что если выбрана задача без названия, кнопки создания отключаются.

### Управление раскрытием дерева

Во всех вкладках со списками задач и в деревьях связей карточки доступны горячие клавиши управления раскрытием:

- **Развернуть вложенные текущего (Ctrl+Shift+Right)** - Развернуть выбранный узел и все его вложенные узлы
- **Свернуть вложенные текущего (Ctrl+Shift+Left)** - Свернуть вложенные узлы у выбранного узла
- **Развернуть все узлы (Ctrl+Alt+Right)** - Развернуть все узлы в активном дереве
- **Свернуть все узлы (Ctrl+Alt+Left)** - Свернуть все узлы в активном дереве

### Удаление задач

Задачи удаляются безвозвратно при нажатии кнопки "❌" в списке задач.
Также при нажатии **Shift+Delete** происходит удаление выбранной задачи.

### Перетаскивание мышью

Во всех вкладках вы можете выполнять действия перетаскивания задачи левой кнопкой мыши. Та задача, которую вы потянули, называется перетаскиваемой.
Та задача, на которой вы отпускаете кнопку мыши, называется целевой.
В зависимости от того, какие кнопки на клавиатуре зажаты, когда вы отпускаете левую кнопку мыши, выполняются разные команды:

- **Без клавиш** - Вложить перетаскиваемую задачу в целевую задачу
- **Shift** - Переместить перетаскиваемую задачу в целевую задачу
- **Ctrl** - Перетаскиваемая задача блокирует целевую задачу
- **Alt** - Целевая задача блокирует перетаскиваемую задачу
- **Ctrl+Shift** - Клонировать перетаскиваемую задачу в целевую как подзадачу

### Поиск и фильтры эмодзи

Эмодзи в названиях помогают группировать задачи. Фильтры показывают их иерархию с раскрываемыми ветвями: можно искать по названию или эмодзи и выбирать несколько включающих и исключающих значений, не закрывая список после каждого выбора.

В плоских списках и карточке задачи видны эмодзи родителей — так проще понять, к каким проектам она относится.

Для ввода эмодзи используйте системную панель: **Win+.** в Windows, **Cmd+Ctrl+Пробел** в macOS. В Linux способ ввода зависит от окружения рабочего стола и настроек ввода.

## Хранение и резервное копирование

Для локальной работы сервер не нужен: задачи хранятся отдельными JSON-файлами в каталоге активного пространства. Его путь виден в настройках хранилища. Desktop допускает абсолютный и относительный путь; стандартный путь при отсутствии настройки — `Tasks` относительно рабочего каталога запуска. Для собственного хранилища удобнее явно указать абсолютный путь.

Настройки обычной установленной desktop-сборки находятся в `Documents/Unlimotion/Settings.json` внутри профиля пользователя; путь может быть переопределён аргументом `--config=<path>`. Debug-запуск из исходников использует `Settings.json` в рабочем каталоге. Перед переносом данных проверьте фактический путь задач в настройках — это отдельный каталог, не обязательно рядом с файлом настроек.

Git подключается отдельно для каждого пространства. В разделе **Резервное копирование** задайте репозиторий и способ авторизации, подключите его и проверьте ручную синхронизацию. Автоматическое резервное копирование нужно включить в настройках. Для SSH можно выбрать или создать ключ; **SSH Key Storage Path** задаёт папку ключей и отдельного `known_hosts`. Конфликты синхронизации разрешаются через соответствующий интерфейс приложения.

Удаление пространства из списка настроек не удаляет его JSON-файлы или удалённый репозиторий. Удаление самой задачи — отдельная необратимая операция.

### Обмен аутлайном задач

Команды **Копировать задачу аутлайном** (**Ctrl+Shift+C**) и **Вставить задачу аутлайном** (**Ctrl+Shift+V**) позволяют переносить иерархию через буфер обмена. В настройках можно включить Markdown и копирование описаний. При вставке приложение показывает подтверждение с числом задач и местом вставки. Маркеры статусов приведены в раскрываемом блоке выше.

## CLI и автоматизация

CLI работает с локальным каталогом задач без запуска интерфейса. Он подходит для скриптов и агентов: читать задачи и связи, создавать задачи, менять критерии и статусы, получать задачу в работу, сохранять вопросы, ответы и результат.

Для установки через `dotnet tool` нужен **.NET 10 SDK**; сам CLI выполняется с .NET 10 runtime. Самодостаточные desktop-сборки отдельной установки .NET не требуют.

```powershell
dotnet tool install --global Unlimotion.Cli
unlimotion-cli status --format json
```

Обновление:

```powershell
dotnet tool update --global Unlimotion.Cli
```

Без `--tasks` CLI использует активное локальное пространство из стандартного файла настроек установленного приложения. Явный `--tasks <каталог>` имеет приоритет; он также нужен для собственного пути конфигурации. Относительный путь из настроек CLI разрешает относительно каталога `Settings.json`.

Цикл агента: `candidates` → `task` → `claim` → вопросы/ответы и результат через `execution` → `execution complete` или `release`. Команды исполнения проверяют владельца и идентификатор аренды (`lease`), а завершение — доступность задачи и выполнение критериев.

Многострочные описания и Markdown сохраняются как исходный текст. Это не означает, что desktop отображает Markdown как форматированный документ.

### Пакетные изменения

`unlimotion-cli unlocked --root <task-id> --format json` выбирает доступные для старта задачи в указанном поддереве. Расширенный ответ `task` содержит `etag` для проверки того, что задача не изменилась после подготовки операции.

Сохраните JSON-запрос вне каталога задач, проверьте его содержимое и сначала выполните предварительную проверку:

```text
unlimotion-cli apply --tasks <task-directory> --request <approved-request.json> --dry-run --format json
unlimotion-cli apply --tasks <task-directory> --request <approved-request.json> --format json
```

Запрос содержит ревизию предложения, автора, причину, предусловия `etag` и операции. CLI проверяет весь граф перед записью и возвращает `preview`, `applied` или структурированную причину отказа. Успешное применение сохраняет квитанцию в `.unlimotion.applies/v1`; повтор идентичного запроса возвращает `alreadyApplied`. Если процесс прервался между транзакцией и записью квитанции, повтор сверяется с фактическим графом, чтобы не применить операции дважды.

При `outcomeUnknown` сначала перечитайте состояние, не повторяйте изменение вслепую. Форматы запросов и подробные правила работы — в [документации CLI](src/Unlimotion.Cli/README.md) и справке `unlimotion-cli --help`.

## Сборка и запуск из исходников

При клонировании `main` вы получаете текущий snapshot разработки. Стабильную сборку или соответствующий ей архив исходников выбирайте на странице Releases выше.

Предварительные требования:

- Git
- [.NET 10 SDK](https://dotnet.microsoft.com/en-us/download/dotnet/10.0), совместимый с `global.json`
- Доступ к NuGet для первого восстановления зависимостей

Выполняйте команды из корня репозитория.

Windows PowerShell:

```powershell
git clone https://github.com/Kibnet/Unlimotion.git
Set-Location Unlimotion
.\run.windows.cmd
```

Linux или macOS:

```bash
git clone https://github.com/Kibnet/Unlimotion.git
cd Unlimotion

# Linux
bash ./run.linux.sh

# macOS
bash ./run.macos.sh
```
